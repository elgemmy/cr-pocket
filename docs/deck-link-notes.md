# Deck copy-link notes

Status: 2026-10-13 · Owner: domain logic (`src/domain/link.ts`, `src/domain/deck.ts`, `src/domain/slots.ts`)

## The official copy-deck link

**Verified shape** (observed live on deckbeacon.app deck pages, October 2026 — the same
`link.clashroyale.com` handoff the game itself generates):

```
https://link.clashroyale.com/en/?clashroyale://copyDeck?deck=ID1;ID2;ID3;ID4;ID5;ID6;ID7;ID8&tt=TOWERID&l=Royals
```

Real example (captured from a live page):

```
https://link.clashroyale.com/en/?clashroyale://copyDeck?deck=26000001;26000000;27000006;26000010;26000030;28000011;28000000;27000008&tt=159000000&l=Royals
```

| Part | Meaning | Status |
| --- | --- | --- |
| `deck` | Eight canonical card ids, `;`-separated | **Verified** against live links |
| `tt` | Tower Troop id (`159000000` = Tower Princess) | Present in every observed deckbeacon link; **not yet verified on a real device** — gated behind `TOWER_TROOP_LINK_VERIFIED = false` |
| `l` | Always `Royals` in every observed link (game-generated and third-party) | Verified as an observed constant; semantics unknown (likely an internal tag) |
| slot/evo parameter | **Does not exist.** No observed link carries Evo/Hero/Wild or slot-position information | Verified absence (Oct 2026) |

Notes on the wire format:

- The inner `clashroyale://copyDeck?...` is appended **raw** after the outer `?` — it is
  *not* percent-encoded in links generated by the game or by deckbeacon. We build it the
  same way, but the parser accepts percent-encoded variants too.
- Observed card order inside `deck=`: Evo slot card first, Hero slot card second, Wild
  slot card third, then the five ordinary cards. We emit this order (it matches our slot
  positions 0/1/2) and expose it as `specialSlotHint` when parsing, but it is an
  **observed heuristic, not a documented contract**.
- The handoff only works on a device with Clash Royale installed; desktop browsers do
  nothing useful with it (hence the QR/copy fallback in the UI).

## What the link cannot do

- **Forms are not transferred.** Evo/Hero/Champion activation must be re-applied in-game.
  This is confirmed by deckbeacon's own guide ("The one thing the link cannot do is turn
  on Evolutions or Hero form") and by RoyaleAPI's mid-March 2026 notes ("the card form
  information isn't maintained when copying decks" — a Wild-slot Hero may even come back
  as an Evolution when the card has both). CR Pocket shows `formsReminder()` output
  ("Set these forms in-game after import") before handoff.
- **No remote write confirmation.** Opening the link only offers the import inside the
  game; never claim a deck was written to the player's in-game slots.

## Accepted paste formats (`parseDeckLink`)

1. Full `https://link.clashroyale.com/en/?clashroyale://copyDeck?...` URLs
2. Bare `clashroyale://copyDeck?...` deep links
3. Percent-encoded variants and links embedded in larger text (YouTube descriptions)
4. `https://royaleapi.com/decks/stats/<key>,<key>,...` — keys are slugified card names
   (lowercase, dots/apostrophes removed, separators → `-`), so a catalog is required to
   map them to ids. RoyaleAPI variant suffixes `-ev1` (evolution) and `-hero` are
   detected as forms; Champion cards map to the `champion` form.

Errors are typed: `not_found`, `wrong_count` (≠ 8 cards), `duplicate`, `unknown_cards`
(with the offending ids/keys).

## Slot rules (March 2026 rework)

Sources: [Supercell mid-March update blog](https://supercell.com/en/games/clashroyale/blog/news/mid-march-update/),
[Supercell support — Cards & Decks](https://support.clashroyale.com/hc/en-us/articles/49484924205595-Cards-Decks),
[RoyaleAPI mid-March update notes](https://royaleapi.com/blog/2026-q1a-update-mid-march-2026).

- Deck = **1 Evolution slot + 1 Hero slot + 1 Wild slot + 5 ordinary slots** (old: 2 Evo + 2 Hero).
  Evo slot: Evolutions only. Hero slot: Heroes **and Champions**. Wild slot: Evolutions,
  Heroes, **or Champions**.
- Wild slot with a dual-form (Evo+Hero) card activates the **Evolution by default**;
  the player can switch in-game. `defaultFormFor` mirrors this.
- **Champions:** support docs say "To use special card forms or Champion Cards, you'll
  need to place them in the right slot in your deck" and describe only the Hero/Wild
  slots as Champion-capable. We therefore warn (`validateDeck` → `champion_slot`)
  when a Champion sits in the Evo or an ordinary slot. This is a **warning, not a
  block**: the exact in-game behaviour for a Champion placed in an ordinary slot is
  unverified (see checklist below).
- A special slot may hold a base card with no active form.
- Ownership/unlock state (from the player's collection) only ever **warns**, never blocks.

## Tower Princess id

`TOWER_PRINCESS_ID = 159000000`. Confirmed as the Tower Princess id in every observed
`&tt=` value paired with the "Tower Princess" label on deckbeacon. Tower troop ids live
in the `159xxxxxx` range in the official API. **Still verify against a live `/v1/cards`
response** during the M0 spike. `towerTroopId: null` on a deck means "unknown → UI shows
the Tower Princess default".
